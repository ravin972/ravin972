## 🧠 How I Engineer

I generally think about backend work through four questions:

**1. What is the actual problem?**
Understand the product requirement before choosing the implementation.

**2. Where does state and responsibility belong?**
Keep APIs, services, data and asynchronous work clearly separated.

**3. What happens when things fail?**
Dependencies fail. Networks timeout. Jobs retry. Users do unexpected things.

**4. How will I know what happened?**
Logs, tests, useful errors and observable system behaviour matter as much as the happy path.
